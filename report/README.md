## ACTIN-Report

ACTIN-Report generates PDF reports for both **Hartwig Trial Search (HTS)** and **ACTIN 2.0** based on the data provided to the system and
the results generated by [ACTIN-Algo](../algo/README.md).

The type and interpretation of the input data differ between the two products:

- **Hartwig Trial Search (HTS)** generates a report of clinical trials matching a set of physician-selected search inputs.
- **ACTIN 2.0** generates a patient-centric report of available treatment options based on the patient's clinical and molecular data.

For simplicity, both products use the `PatientRecord` data model as the common input structure. For HTS, the `PatientRecord` represents the
physician-selected search inputs and should not be interpreted as a comprehensive representation of the patient's clinical context. For
ACTIN 2.0, the `PatientRecord` represents the patient's clinical record used by the system.

Example PDF reports:

- [Hartwig Trial Search](../system/src/test/resources/example_reports/EXAMPLE-LUNG-01.actin.pdf)
- [ACTIN 2.0](../system/src/test/resources/example_reports/EXAMPLE-CRC-01.actin.pdf)

This application requires Java 17+ and can be run as follows:

```shell
java -cp actin.jar com.hartwig.actin.report.ReporterApplication \
   -patient_json /path/to/patient_record.json \
   -treatment_match_json /path/to/treatment_match.json \
   -output_directory /path/where/pdf/is/written
```

The following assumptions are made about the inputs:

- The patient record JSON adheres to the data model defined
  in [PatientRecord](https://github.com/hartwigmedical/actin-datamodel/blob/master/datamodel/src/main/kotlin/com/hartwig/actin/datamodel/PatientRecord.kt).
  For HTS, this structure contains the physician-selected search inputs rather than a comprehensive patient clinical record.
- The treatment match JSON is the output generated by [ACTIN-Algo](../algo/README.md).

### Report Configuration

A report configuration can be provided via the `-override_yaml` parameter to configure the report and specify the type of report to
generate.

The report type is defined by `ReportConfiguration.ReportType` and can be one of:

- `PERSONALISATION` — generates the patient-centric ACTIN 2.0 report.
- `TRIAL_MATCHING_NON_MEDICAL` — generates the Hartwig Trial Search report for non-medical device use.
- `TRIAL_MATCHING_RESEARCH_USE_ONLY` — generates the Hartwig Trial Search report for research use only. Used in the Progene study.

By default, `TRIAL_MATCHING_NON_MEDICAL` is used. A different report type can be selected by providing a report configuration via
`-override_yaml`.
